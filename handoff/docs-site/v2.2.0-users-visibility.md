## Section A (User Profile): Roles and the Users dashboard

The **Users** dashboard lists people with their email, name, role, join date and last login, plus four summary cards: Total Users, Active Users, Never Logged In and Inactive 30+ Days. *(Changed in v2.2.0: platform users now see every tenant.)*

What each role gets:

| Role | Sees the Users menu option | Users listed |
|---|---|---|
| `platform` | Yes | **Every user in every tenant**, with an extra **Tenant** column. The page subtitle reads "All tenants". |
| `owner` | Yes | Users in their own tenant only |
| `admin` | Yes | Users in their own tenant only (same as owner) |
| `user` | No | No access |

- The summary cards always cover the same users as the list. For a platform user, that means totals across all tenants.
- `owner` and `admin` behave identically here.
- The Users option appears in two places: the sidebar (**Users**) and the organisation menu in the header (**Manage Users**). Both are hidden from the `user` role. *(Before v2.2.0 the `user` role could see the links but was turned away on click.)*

Replacement rows for the v2.1.0 Roles table:

| Role | Meaning |
|---|---|
| `owner` | Created the tenant at sign-up. Can manage tenant settings and see the tenant's users. |
| `admin` | Same management access as owner. |
| `user` | Standard member of the tenant. Cannot see the Users dashboard. |
| `platform` | The site operator, above tenant owners. Sees users across all tenants on the Users dashboard. Elsewhere it works within one tenant like any other role. |

## Section B (Security): Tenant isolation and the platform role

FrankPHP keeps each tenant's data separate:

- **On every request,** the tenant in the URL must match the logged-in user's tenant.
- **On every database query,** results are filtered to a single tenant.

**The Users dashboard for the `platform` role is the one deliberate exception.** It shows users from all tenants. Three rules keep it safe:

1. **It depends only on who is logged in.** The decision comes from the logged-in user's role. No URL, query string or form value can switch a non-platform user into the all-tenants view.
2. **It still uses single-tenant queries.** FrankPHP builds the list one tenant at a time and never runs a query across the whole users table.
3. **The access check is on the server.** Visiting `/tenant/{id}/users` as a `user` sends you back to the dashboard with `?error=forbidden`. Hiding the menu link is a convenience only. If you customise your navigation, don't rely on hidden links for security.

**Treat `platform` as a highly privileged role.** Anyone with it can see the email address, name, role and login activity of every user on the site. Give it only to the people who run the platform.

## Section C: Upgrading to 2.2.0

1. **Replace the `framework/` folder** with the 2.2.0 release, as for any update. No database migration is needed.
2. **Update your app's views** to show the new Tenant column and hide the Users links. These files belong to your app, so the framework update doesn't change them. Copy these changes in:

   **`app/Views/users/management-dashboard.php`**: show the tenant when the list spans all tenants. The page receives `$crossTenant` (true or false), and each user row has a `tenantName`.

   ```php
   <th>Name</th>
   <?php if ($crossTenant) : ?><th>Tenant</th><?php endif; ?>
   ...
   <td><?= htmlspecialchars($row['name']) ?></td>
   <?php if ($crossTenant) : ?><td><?= htmlspecialchars($row['tenantName']) ?></td><?php endif; ?>
   ```

   **`app/Views/partials/app-nav.php`** and **`app/Views/partials/app-header.php`**: wrap each Users link so the `user` role doesn't see it.

   ```php
   <?php if (in_array($user['role'] ?? '', ['platform', 'admin', 'owner'], true)) : ?>
       ... the Users / Manage Users link ...
   <?php endif; ?>
   ```

   If you skip this step, the page still works. Platform users see all tenants' users but without the Tenant column, and the `user` role still sees the links but is refused on click.
3. **Only if your app builds `UserManagementService` itself** (most apps don't): it now also needs the tenant model, `tenantModel: new \Frank\Models\Tenant()`. The framework's own setup already does this.
